# M6-01 六类固定评测数据集

## 范围

`code/evals/datasets/v1/` 保存版本固定的案例清单，`code/evals/fixtures/v1/` 保存不含真实客户信息的主数据与输入文件。数据集包含正常、异常、歧义、越权、超额、重复提交六类，每类至少六例；另设两个等待点恢复、并发争用和提交结果未知专项。专项标签独立于六类计数，不能用普通文本案例替代。

所有用例固定使用 `Asia/Hong_Kong` 时区和 `2026-10-16T09:00:00+08:00` 时钟。角色、合同、物料、数量、字段预期、工具约束和订单/批准/占额事实均为合成数据。文件夹具通过 SHA-256 固定内容。

## 数据契约

- `manifest.json`：数据版本、主数据及输入夹具版本、固定时钟、时区、类别门槛、文件清单和案例数。
- `cases.jsonl`：每行独立案例，包含唯一 ID、类别/标签、固定时间、角色与合同夹具、前置状态、输入、动作、工具约束、字段/状态/错误预期，以及订单、批准和占额断言。
- `fixtures/v1/master_data.json` 与 `index.json`：合成用户、部门、合同、物料和文件索引。`mixed_batch.xlsx` 使用产品固定中文表头；`damaged.pdf` 是无敏感信息的损坏文件输入。
- `code/evals/build_dataset.py`：以 JSONL 案例和主数据文件为唯一源，确定性重建 Excel/PDF 文件、文件索引和数据清单；案例断言使用固定的 `source`、`operator`、`expected` 结构供后续 runner 消费，说明性业务规则单独放在 `rules`。

期望值描述规则验收契约，不代表这些案例已由模型执行或取得在线成绩。在线模型、真实外部服务验证以及评测运行器属于后续工作；本 issue 仅交付固定数据和数据契约检查。未知提交结果、恢复和并发案例提供可执行断言目标，不在此实现 runner。

## 验证

在 Windows PowerShell 中从仓库根目录执行：

```powershell
uv run --project code/backend python code/evals/build_dataset.py
uv run --project code/backend pytest code/tests/issues/test_issue_036.py -q
```

首条命令会确定性重建并更新仓库中的本地夹具、索引和清单；第二条命令只读检查数据版本、六类数量、专项数量、唯一 ID、字段契约、夹具引用、时区、文件哈希和明文密钥模式。两条命令均不连接 Docker、数据库或模型服务，不产生业务数据副作用。预期全部断言通过；失败时根据 pytest 案例定位数据或哈希差异。该检查不等价于在线模型评测或数据库安全不变量验证。
