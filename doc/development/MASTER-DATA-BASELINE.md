# 主数据台账实现说明

本文记录合同台账、标准物料和别名管理的接口约束与验证入口。接口仅供系统管理员使用；服务端会话中的部门范围决定数据可见范围。

## 接口

所有接口位于 `/api/v1/admin`：

- `GET /departments`、`GET /lookups`：读取当前管理员可访问的部门及合同表单选项。
- `GET /contracts`、`GET /contracts/{id}`：筛选合同并读取明细、占用金额、订单数和剩余额度。
- `POST /contracts`、`PATCH /contracts/{id}`：维护合同及明细。修改合同须提交 `expected_version`；累计占用金额和订单数是只读账本，合同总额不得低于占用金额或已存在订单金额。
- `GET /materials`、`POST /materials`、`PATCH /materials/{id}`：维护标准物料和业务别名。修改须提交 `expected_version`；别名规范化用于检索，不会强制跨物料唯一。
- `GET /materials/match-preview`：调用现有物料匹配服务，完整返回候选；多候选会要求人工确认。

写请求必须携带登录响应提供的 `X-CSRF-Token` 并来自同源。错误分别使用权限拒绝、版本冲突、重复编号/编码、额度下限和无效输入等明确错误码。审计记录与主数据变更同事务提交，保存操作者、变更前后摘要及输入哈希。物料版本迁移为 `e24d903f7a11`。

主数据更新只影响后续检索和新草稿，不回写既有草稿修订或订单快照。停用合同会被草稿预检拒绝。最终正式订单提交入口尚未由依赖交付提供，因此“最终提交再次拒绝停用合同”仍待该入口交付后验证；本实现不新增另一个 issue 的正式下单流程。

## 验证

在仓库根目录运行：

```powershell
pwsh -NoProfile -File code/scripts/verify_issue_020.ps1
```

脚本使用 `code/backend/.env` 中的本机 Compose 基础配置，覆盖为随机演示密码、临时签名密钥及随机宿主端口，建立唯一 Compose 项目并创建一次性 PostgreSQL 数据卷。它运行 Alembic 升级与漂移检查、初始化演示账号、启动真实 MCP 服务，再执行 #20 断言及合同规则回归。完成后只清理该随机项目。测试会在隔离数据库内插入演示额度和临时物料；额度在用例结束时恢复，临时物料删除，审计记录随隔离数据库销毁。

此验证不调用在线模型，也不代表最终正式下单验收。需要 Docker Desktop、网络可拉取 Compose 镜像，以及本机 `.env` 中可用的隔离数据库配置；脚本不会读取或打印模型密钥。
