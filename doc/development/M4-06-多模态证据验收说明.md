# M4-06 多模态证据验收说明

工作台支持文本描述、PDF/图片上传和 Excel 分组校验。PDF/图片由后端现有解析器实际提取；页面显示原始附件、页码定位、识别字段、缺失项与冲突候选。只有经办人逐项选择并提交后，字段才会进入新草稿版本。合同号、客户名和金额等不能安全转换为主数据引用的识别结果仅显示来源，须通过业务控件或人工补充。

PDF/图片上传先生成受控附件记录；任务创建时在同一数据库事务中建立任务附件授权，后续可通过任务附件列表和原文件接口回查。任务草稿更新继续使用现有乐观锁；文件确认记录绑定附件、页码、解析定位、原值、采纳值和服务端确认人，并写入审计事件。解析本身不创建订单或批准订单。Excel 复用只读分组预览接口，失败重试复用已上传附件，不重新上传。

## 验收命令

在 Windows PowerShell 中，从仓库根目录运行：

```powershell
./code/scripts/verify_issue_027.ps1
```

命令要求已安装 Docker Desktop、uv、Node.js/npm，并在 `code/backend/.env` 配置演示验收数据库环境。脚本为本轮使用独立 Compose 项目、临时端口、数据库卷和附件卷；不会重启或清理日常开发 Compose。完成后仅清理带本次随机项目名的隔离容器、卷及镜像。

脚本执行前端生产构建；在隔离后端内运行 Ruff、Python 编译、Alembic 一致性检查及 issue #18、#22–#27 相关 API 回归。#27 自动化验收使用固定 PDF 文本样本，通过真实附件上传和后端 PDF 解析，验证页码定位、任务授权、幂等关联、字段确认、草稿版本/冲突和无订单副作用。该样本无需在线模型或 OCR 服务。

## 验证边界

- 本地静态验证：前端 `npm run build`、后端 Ruff 与 `compileall`。
- 隔离服务集成：运行上述验收脚本；它使用独立 PostgreSQL、真实 API 和真实 PDF 解析。
- 在线模型评测：本 issue 未要求模型直接读取附件，附件字段应用依赖解析器和明确的用户确认；不将离线 PDF 样本描述为在线模型评测。
- 图片 OCR 依赖配置的本地 Tesseract 及语言包；未配置时界面显示解析失败，保留上传文件和订单描述，可显式重试，不会静默填入草稿。
- Excel 校验为只读预览，不在本验收中自动创建订单或审批。
