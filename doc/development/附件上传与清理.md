# 附件上传与清理

## 接口行为

- `POST /api/v1/artifacts` 接收 `multipart/form-data`：`file`、`parse_intent`（`contract_pdf`、`receipt_image`、`order_xlsx`），可选 `task_id`。请求需同源 Origin、有效会话及 CSRF。
- HTTP 201 的 `state=STORED` 只表示文件已验证并持久化，不表示已解析或创建订单。
- `GET /api/v1/artifacts/{artifact_id}` 返回经授权的元数据；`GET /api/v1/artifacts/{artifact_id}/content` 单独校验原文件读取权限。
- `GET /api/v1/tasks/{task_id}/artifacts` 列出任务已关联附件。
- 对象使用 128 位随机键存储，原文件名仅用于显示；API、审计和任务事件不返回对象路径或存储键。

## 限制与安全检查

| 类型 | 文件大小 | 内容限制 |
|---|---:|---|
| JPG / PNG | 10 MiB | 校验真实图像格式、解码完整性、像素数和边长 |
| PDF | 20 MiB | 校验 PDF 可读、非加密且不超过 20 页 |
| XLSX | 10 MiB | 校验 OOXML 工作簿、拒绝宏、控制解压量/压缩比和内部文件数量，最多 500 条非空明细行 |

文件先写入权限受限的临时目录，按块计算 SHA-256；通过格式检查后才原子移动至对象目录。传输总大小在 multipart 解析前受限，格式检查再次按类型限制实际文件字节数。路径只接受随机十六进制键，文件名不会参与路径计算。

## 保留与清理

运行 `uv run python -m app.storage.cleanup` 可按 `ARTIFACT_RETENTION_DAYS`（默认 30 天）清理过期对象。清理保留数据库元数据和审计引用；存在活动任务、正式订单或字段证据引用的文件不会删除。清理先在事务中将记录标记为 `DELETED`，提交后再删对象；对象删除失败时下次运行重试。该命令只处理附件记录，不扫描或删除未知文件。

## 验证

运行 `code/scripts/verify_issue_022.ps1`。脚本用随机 Compose 项目名和隔离数据库/附件卷，执行迁移检查、Ruff、编译及上传 API 集成验收，结束后只清理本次随机项目。需要 Docker Desktop、`code/backend/.env` 中可用的数据库配置和网络可拉取镜像；脚本不会读取或打印模型密钥。
