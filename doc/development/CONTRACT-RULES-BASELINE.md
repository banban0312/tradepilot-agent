# 合同与字段规则预检基线

Issue #5 增加只读领域预检服务。它基于数据库当前合同、客户、项目、物料、合同明细及余额快照，返回结构化字段问题、物料候选、逐行金额/数量预览和预检时间。预检仅用于决定草稿能否进入人工审批，不会锁余额、占额或创建订单；最终订单事务必须按 Spec §5.4 重新检查权威余额与授权。

## 规则

- 合同必须属于登录会话授权部门，方向匹配、状态为 ACTIVE，并在明确传入的业务日期有效。不存在和跨部门合同均返回相同的资源不存在语义。
- 草稿客户和项目必须与合同关联一致；客户必须有效，项目与客户/合同属于相同部门。物料必须有效、已加入合同，所选标准规格及订单单位必须相符，不执行隐式单位换算。
- 缺失单价时仅使用该合同物料行的已配置价格，并记录 `MASTER_DATA` 来源及合同明细定位；显式单价与合同价格不一致则阻断。主数据没有价格时要求补充有效含税价格。
- 交期不能早于业务日期，并须在合同有效期内。数量和单价仍遵守 Issue #4 的 Decimal 正数与精度规则。
- 剩余额度按合同总额减去 `contract_balances` 中已占用正式订单金额。草稿、待审与本次预检都不改变余额。金额等于余额允许进入下一步，大于余额返回超额差额并阻止审批。
- 配置了合同物料数量上限时，按物料和单位汇总本次明细并减去既有正式订单数量占用。合同未设置订单张数上限时，不从金额推算张数，结果明确标为无限制。
- 缺少合同余额或已配置数量额度的余额行时失败关闭并返回对应问题，不把缺失数据伪装成零余额/零占用。
- 未确认标准物料时只返回匹配候选，绝不自动挑选规格。比如“HRB400E”没有直径时不能猜成 12mm 或 16mm。

```powershell
Copy-Item code/backend/.env.example code/backend/.env
pwsh -File code/scripts/verify_issue_005.ps1
```

验证入口使用独立 Compose 项目、数据库卷和演示账号，并在退出时只清理该项目。Issue #5 测试覆盖合同 15 万元余额对 22 万元订单返回 7 万元超额、等额预检可继续、预检前后余额不变、合同方向/状态/部门、客户关联、单位/价格/数量/交期以及未确认物料候选。验证不连接真实 ERP 或在线模型。

本服务目前由后续 MCP/Agent issue 接入工作流；预检余额可能随其他正式订单变化，不构成提交授权或并发占额保证。
