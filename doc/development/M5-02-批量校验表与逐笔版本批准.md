# M5-02 批量校验表与逐笔版本批准

## 实现范围

- 工作台完成 Excel 预览后可建立持久批次并进入 `/imports/{batch_id}`。批次创建使用附件 ID 生成稳定幂等键，重复提交不会重复创建批次。
- 批次页展示源工作表/行、候选订单、分组问题、任务状态及批次计数；按需读取子任务详情，避免每次轮询对全部历史任务发请求。
- 对尚未建立子任务的异常组，可修正交期、收货地址、联系人及 Excel 物料行字段。接口保留并校验候选数据，使用 `edit_version` 乐观锁；修正后重新运行必填项、合同/客户/项目、金额和额度检查。
- 仅完全有效且额度足够的分组才建立独立任务；每个任务沿用既有草稿、人工批准、版本摘要和确定性额度校验。已建立任务的草稿修改继续调用既有任务草稿接口。
- 批量批准先刷新批次与每个任务的最新状态，再逐项请求既有 `APPROVE` 接口。确认信息包含每笔合同、金额、草稿版本及内容摘要；任何一笔失败均单独显示结果，不把多个审批合并成一个决定。
- 校正操作写入追加式审计事件。额度预览扣除数据库已占用额度及同批次其他尚未创建任务的有效候选金额；最终额度仍以正式订单事务锁中的实时检查为准。

## 接口与存储

- `PATCH /api/v1/imports/{batch_id}/groups` 接受 `sheet`、`group_id`、`expected_version` 和修正后的 `candidate`。
- `ImportBatchItem.candidate_json` 保存无效组候选；`edit_version` 从 1 开始，只有版本匹配时才可修改，成功后递增。过期版本返回 409。
- 修正范围不能变更订单类型、合同、客户、项目、币种、业务字段、证据、物料关联或 Excel 明细行数。合同/项目等主数据无法匹配时，保留问题并提示修正来源表后重新导入。
- 修正后可入队时，子任务使用批次和工作表/分组组合生成的稳定 UUID，关联原附件和源行，加入现有 Worker 队列；批次停止标记会阻止继续修正。
- 路由只允许批次所属经办人修改；读取批次时仍按现有部门权限检查。数据库行锁与 `expected_version` 一起防止并发覆盖。

## 页面与审批语义

批次表可按分组勾选可批准项。勾选键包含工作表和分组 ID，以免同名分组冲突；总额按整数分计，避免浮点误差。提交前重新读取服务端状态，草稿版本、摘要、额度或审批资格变化后要求重新核对。逐项调用接口并分别呈现结果；服务端仍校验真实登录用户、当前草稿版本/摘要、权限及额度。

未建立任务的异常组不会进入审批队列。批次表行内修正可处理可编辑字段；合同或项目引用错误需修复 Excel 来源后重新导入。已进入任务的候选应在任务草稿中修改，既有审批会因内容摘要变化而失效。

## 本地验收

```powershell
pwsh -NoProfile -File code/scripts/verify_issue_030.ps1
```

脚本先构建前端，再创建独立 Compose 项目、数据库和附件卷，运行迁移一致性检查、Ruff、compileall、演示主数据以及 #29/#30 隔离 API 集成测试。不会启动主 Worker、调用在线模型或重启/清理主开发服务；退出时只删除该脚本创建的隔离资源。

关键断言覆盖批次持久化、幂等与停止回归、异常组修正后校验并创建子任务、版本递增、过期版本冲突。该验收不替代在线模型评测，也不创建正式订单。
