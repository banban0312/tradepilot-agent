# M6-06 性能、稳定性、兼容与备份恢复验收

本说明对应 GitHub issue #41。验收数据仅适用于本机隔离 Compose 环境，不代表生产 SLA。

## 环境准备

- Windows + PowerShell 7、Docker Desktop 和 `uv`。
- `code/backend/.env` 已按 `code/backend/.env.example` 配置数据库变量；脚本会在临时 Compose 覆盖中关闭模型调用，使用随机密码、签名密钥、加密密钥、端口、Compose 项目名和数据卷。
- Chrome / Edge 当前主版本使用 Windows 可执行文件；前一主版本由官方浏览器包运行。Edge 前一主版本测试需将微软官方 Edge 154 Linux x64 `.deb` 放入 `code/artifacts/performance/browsers/edge-linux-154.0.4258.62-amd64.deb`，SHA-256 必须为 `F425DEA59F0A8BAC00201685A070E947543C57D135C130BA73E0863CF2C506B1`。脚本只在临时 Node 容器内安装该包，不改动 Windows 浏览器。
- 浏览器验收需要 Node.js 22 或更新版本；通过 DevTools 实际登录后检查订单中心和新任务工作台，并在两种分辨率保存截图。
- 本机已有前端镜像 `tradepilot/web:local`。可在 `code/` 下执行 `docker compose build web` 生成镜像；验收脚本只为其创建随机标签，不启动或清理默认 Compose 项目。
- 脚本只清理本次随机命名的 Compose 项目和镜像。报告留在 `code/artifacts/performance/`（该目录被 Git 忽略），不会被提交。

## 命令

在仓库根目录运行：

```powershell
pwsh -File .\code\scripts\verify_issue_041.ps1 -SkipSoak
```

短验收会运行 issue #41 的 API、容量、XLSX 上传、任务恢复、附件备份/还原、浏览器页面加载，以及 #6、#12、#16、#22、#29、#35 的相关回归。完整验收运行默认 8 小时；可以在后台启动：

```powershell
Start-Process pwsh -WindowStyle Hidden -ArgumentList @(
  '-File', (Resolve-Path '.\code\scripts\verify_issue_041.ps1').Path
)
```

也可以指定 1 至 24 小时：

```powershell
pwsh -File .\code\scripts\verify_issue_041.ps1 -SoakHours 8
```

不要对该次运行使用 `docker compose down`；脚本结束时会自动清理自己的随机项目。`-SkipRegression` 仅用于调试，不得作为交付结果。

## 覆盖与判定

- 记录并核对并发上限 5、图片 10 MB、PDF 20 MB/20 页、XLSX 10 MB/500 行配置。
- 通过真实隔离 API 测 100 次业务请求，要求 P95 ≤ 1 秒且 ≤ 300 毫秒；上传 100 行 XLSX，要求响应成功、解析行数正确且耗时 ≤ 10 秒。
- 以 20 个过期任务为一批重复 20 批，要求每批恢复 20 个任务且 P95 ≤ 2 秒。
- 协调停止 API/Worker 后执行 PostgreSQL 自定义格式快照与克隆库恢复；比较任务、等待、审批、订单、订单明细、额度、附件和字段证据数量；验证文件来源证据仍指向附件记录、附件文件 SHA-256 一致，并从已还原的 LangGraph 检查点继续同一任务。
- 运行期间每分钟记录 API readiness 与数据库、评测库、MCP、API、Worker 健康状态，同时比较容器 ID 和 Docker 重启计数，捕捉采样间隔内的崩溃重启；8 小时报告只有在所有样本正常且没有非预期退出时才判通过。
- 浏览器报告逐个记录发现的浏览器版本、两种分辨率下的真实登录、订单中心读取、新任务工作台加载与页面横向溢出断言；每个页面均保存截图。此 smoke flow 不创建任务或正式订单，不能代替模型提单、人工审批与订单提交的端到端验收。

## 结果解释

- 性能、上传、恢复、备份和还原数据保存在各自随机报告目录的 JSON 文件中。
- `browser-compatibility.json` 中标记为 `unavailable` 的浏览器版本不算兼容通过。必须检查 Chrome 和 Edge 当前、前一主版本是否均有实际结果；未覆盖的提单、人工审批与订单提交流程仍需单独验证。
- 未生成 `stability-summary.json` 或报告里的 `result` 不是 `passed` 时，8 小时稳定性验收未通过/未完成。
- 每次运行独立，失败时保留对应报告和日志以便定位；脚本返回非零退出码。
