# M5-05 历史任务与执行轨迹

## 范围

历史列表复用任务快照和部门权限，支持状态、订单类型、输入来源、关键词与创建时间筛选；批次子任务附带批次及分组树。点“打开原任务”会进入原 task ID，继续与恢复规则由服务端当前状态决定。

`GET /api/v1/tasks/{task_id}/trace` 使用任务可见性校验，按 `start_at + span_id` 稳定游标分页。返回真实 TraceSpan 的模型/工具节点、尝试次数、协议、耗时、受控结构化输入输出摘要、失败码及审批/订单关联。轨迹摘要会过滤原始正文、工具参数值和未列入白名单的字段；不返回隐藏思维链。

Token 用量只在每个模型 span 均含非负完整 usage 时聚合。`tokens: null` 与 `usage_status: unavailable` 表示无真实用量；覆盖率为空表示没有模型调用。模型、工具耗时分别求和。人工等待依据持久任务状态事件的进入/离开时间计算，当前等待单独标为进行中，不计入模型或工具时间。

历史列表过滤参数：`state`、`order_type`、`input_type`、`q`、`created_after`、`created_before`、`cursor`、`limit`。时间使用 ISO 8601 时区时间。轨迹接口参数为 `cursor`、`limit`。两类游标均绑定其资源排序键；历史关键词可匹配任务 ID、会话标题、开始文本及关联合同编号、客户/项目编码和名称。

## 验证

在仓库根目录运行：

```powershell
pwsh -NoProfile -File code/scripts/verify_issue_033.ps1
```

脚本复用隔离 Compose 验收框架，分配随机项目名、临时端口、独立 PostgreSQL 和附件卷。结束时只清理由脚本创建的随机 Compose 项目；不停止、重启或清理默认开发环境。依赖由 `uv` 安装/执行，脚本不会配置在线模型，也不启动 Worker。

验收包含历史筛选、真实数据库轨迹分页、缺少 usage 不显示为 0、工具耗时、结构字段脱敏和跨部门不可见。此结果属于隔离服务集成；没有执行在线模型调用，不能据此宣称在线模型 Token 或外部 MCP 联调通过。

## 当前边界

- 单个任务轨迹事件为便于回查最多返回前 1000 条，并通过 `events_truncated` 明确提示达到上限；耗时统计基于完整状态迁移查询，span 独立按游标分页。超出事件上限时，可使用现有任务事件流的序号游标续查。
- 附件证据仍通过现有任务附件授权接口读取，不将附件原文复制到轨迹响应。
