# Excel 模板与订单分组校验

## 能力范围

- `GET /api/v1/imports/template` 返回简体中文 XLSX 模板，含“订单明细”和“填报说明”工作表。
- 先通过 `POST /api/v1/artifacts` 以 `order_xlsx` 意图上传文件，再用 `POST /api/v1/imports/preview` 提交附件 ID 取得只读预览。
- 同一工作表内相同“订单分组”合并成一个候选订单；各明细保留 `artifact_id`、原始单元格值、工作表名和单元格坐标。
- 结构完整的结果只代表候选草稿已分组，不代表物料已确认、合同额度校验已锁定、可以审批或能创建正式订单。

## 模板列

| 列 | 填写规则 |
|---|---|
| 订单分组 | 同一订单多行使用相同编号，不同订单使用不同编号 |
| 订单类型 | 销售或采购，且须与有效合同类型一致 |
| 合同编号 | 当前部门可访问的合同完整编号 |
| 项目 | 必须与合同关联项目名称或编码一致 |
| 地址、联系人、交期 | 同组各行须一致 |
| 物料名称、规格、数量、单位、含税单价 | 每行明细必填；数字大于零，最多 6 位小数 |

模板限制 XLSX 10 MB、最多 500 条明细行；宏、公式字段、损坏或伪装格式均拒绝。所有单元格提示包含工作表、行号、列号和单元格引用。交期会核对合同有效期；空模板返回无明细提示。

## 状态与安全边界

- `READY_FOR_REVIEW`：字段结构完整、合同/项目关系匹配且预览额度未超；仍须确认物料和运行后续业务校验。
- `NEEDS_CORRECTION`：字段缺失/格式错误、组内主档冲突、合同或项目不匹配、额度不可用等。
- `OVER_QUOTA_REVIEW`：按当前合同余额和导入顺序计算的候选金额超过剩余额度。该预览不锁定额度；后续提交须再次服务端核验。
- 公式不求值，工作簿以只读模式加载。附件 ID 仍执行当前用户、部门和任务关联鉴权；预览审计关联上传文件 SHA-256。
- 上传和预览不会生成持久批次、任务或正式订单；持久批次与子任务由后续批量处理能力实现。
