# M5-01 批次父子任务与停止恢复

## 实现范围

- `POST /api/v1/imports` 对 XLSX 原件重新做 SHA-256 完整性检查和服务端分组校验，建立持久批次；只有 `READY_FOR_REVIEW` 分组会创建独立 `AgentTask`、START 命令和持久作业。缺字段、预览超额组仍保留在批次结果中，但不会创建子任务。
- `GET /api/v1/imports/{batch_id}` 返回批次状态、源工作表/行、独立 task/checkpoint 入口、最新任务错误和正式订单关联。
- `POST /api/v1/imports/{batch_id}/stop` 设置停止标记并取消仍在 `READY` 队列中的任务。运行中或已领取的作业继续执行；它们的结果不会被回滚。操作通过与 Worker 领取相同的事务级 advisory lock 确定领取和停止的先后顺序。
- 父批次使用账号范围幂等键及请求哈希；每个子 task 使用稳定 UUID、独立图检查点，并关联原始 Excel 附件和源行。
- 创建批次与停止批次写入追加式审计事件；被停止的子任务同时写入任务状态事件和 `BATCH_STOPPED` 结果。
- Worker 已有全局并发上限为 5；批次复用该领取器，不另建队列或放宽并发限制。合同额度仍由现有订单提交事务锁定并实时复核。

批次创建不代表审批或下单成功。每个子任务仍运行既有 LangGraph、真实 MCP 工具、确定性校验和人工审批流程；失败项保持独立，可通过既有单任务恢复能力处理。此 issue 不实现批量修改/批量批准页面（由后续 issue 负责）。

## 接口调用

批次创建需要已登录经办账号、CSRF 头和 `Idempotency-Key`：

```http
POST /api/v1/imports
Idempotency-Key: order-import-20261019-001
X-CSRF-Token: <当前会话令牌>
Content-Type: application/json

{"artifact_id":"<已上传的 order_xlsx 附件 UUID>"}
```

查询 `GET /api/v1/imports/{batch_id}`；停止 `POST /api/v1/imports/{batch_id}/stop`（需要 CSRF）。重复创建时，相同 key 和附件返回同一批次；相同 key 用于其他附件返回 409。接口仅接受调用者本人上传且仍为 `STORED` 的 XLSX 附件。

## 状态和并发语义

- `QUEUED` / `RUNNING`：至少一个子任务已入队或执行。
- `STOPPING`：停止已登记，尚有已领取/运行/等待审批的子任务。
- `STOPPED`：停止后没有仍在处理的子任务；已领取任务的最终状态仍逐笔显示。
- `COMPLETED`：所有订单组任务完成。
- `PARTIAL`：存在缺失、超额、规则阻断、失败或拒绝项。
- 子组状态 `STOPPED` 仅表示队列尚未领取时被安全取消；`STARTING` 表示 Worker 已领取，停止请求不会撤销该运行。

停止与 Worker 的五路并发领取使用同一事务锁。若 Worker 先领取，该子任务继续；若停止先取得锁，尚未领取的 READY 作业会被置为失败终态，启动命令会被拒绝，任务记录 `BATCH_STOPPED`。重新查询可核验这些数据库记录；隔离测试不启动 Worker，所以不需要外部模型凭据。

## 本地验证

```powershell
pwsh -NoProfile -File code/scripts/verify_issue_029.ps1
```

脚本创建随机 Compose 项目、独立数据库和附件卷，只启动 `db`、`mcp`、`api`，不启动主 Worker、不调用在线模型；使用 `uv run --frozen` 完成 Alembic、Ruff、compileall 和 #010、#017、#018、#022～#029 回归。退出时只清理该随机项目的卷和专用镜像，不重启或清理主开发服务。

仅重跑当前 issue 时可用 `pwsh -NoProfile -File code/scripts/verify_issue_029.ps1 -IssueOnly`，它仍创建并清理全新的隔离环境。

关键断言包括：正常/缺失/超额组混合、行号和源附件关联、重复幂等键、冲突请求、每批 6 项时最多 5 项可领取、停止取消未领取项且保留已领取项。该验证是隔离真实 API/数据库集成，不是在线模型评测，也不创建正式订单。

若启动失败，先检查 Docker 可用、`code/backend/.env` 依赖配置齐全、随机端口未被本机安全软件拦截。失败日志仅来自随机项目；可按脚本输出的项目名核对清理结果，不要对主 Compose 执行全局 `down --volumes`。
