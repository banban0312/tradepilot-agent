# 正式订单列表与详情

订单中心只回查已提交的正式订单。正式订单只能由既有的人工批准及原子提单流程创建；本模块不提供写入订单或修改审批的接口。

## 接口

- `GET /api/v1/orders?type=&contract=&project=&state=&from=&to=&limit=&offset=`：按销售/采购、合同编号片段、项目编号或名称、正式状态和创建日期筛选。`from`/`to` 按 UTC 日期解释，结束日包含在范围内；结果按创建时间和订单 ID 倒序分页。
- `GET /api/v1/orders/{order_id}`：读取订单主档和不可变明细、绑定批准版本/内容摘要、审批人、当前合同余额、已记录的字段来源元数据、任务审计摘要和任务轨迹入口。
- 两个接口都要求登录业务经办人或审批人，并由会话部门范围过滤。系统管理员身份本身不隐式授予业务订单访问权。跨部门详情统一返回 404，避免资源枚举。
- 详情使用批准记录绑定的草稿版本，并核对订单、批准和版本内容哈希；必要快照缺失时返回明确服务错误，不从当前可变草稿拼造历史订单。
- 字段来源仅返回批准版本的来源类别、页码/单元格定位和确认人，不返回文件或消息 ID、原文、接受值，也不提供绕过附件鉴权的 URL。订单详情的任务链接使用现有任务工作台与轨迹查询权限。

## 本地验证

前置：安装 Docker Desktop，并按 `code/backend/.env.example` 配置本机 `code/backend/.env`。验证脚本创建随机项目名、端口、临时演示密码和独立 PostgreSQL 卷，不连接开发数据库；退出时只清理该隔离项目。

```powershell
pwsh -NoProfile -File code/scripts/verify_issue_019.ps1
```

脚本通过 `uv run --frozen` 执行迁移漂移、Ruff、Python 编译、Issue #16 原子提单回归与 #19 API 验收，再执行前端 TypeScript 检查和生产构建。API 验收在真实隔离 PostgreSQL 与 FastAPI 服务上执行，订单数据由已验证提单服务和固定测试输入建立；它不代表在线模型、附件存储或外部 ERP 已验收。失败时脚本打印隔离服务日志并返回非零状态。

## 依赖与能力边界

本接口依赖 #16 已合并的正式订单、明细、额度占用和审批绑定，以及 #7 的登录会话与部门范围。详情回查已保存的 FieldEvidence 和 AuditEvent；文件原文下载仍由附件能力自身鉴权，不因能够查看订单而开放。
