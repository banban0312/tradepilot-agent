# 可观测性持久化基础

本文说明 M1-06 建立的后端持久化能力，以及后续任务编排、模型/MCP 调用和访问 API 的集成边界。对应验收依据为 PRD FR-18/19、AC-19/20、NFR-09/10/14，Spec §5.2、§5.5、§8.4，以及原型 06（执行轨迹）和 23（操作审计）。

## 数据与事务

- `trace_spans` 持久化真实执行区间、trace/父子关系、可信 actor、尝试次数、执行模式、协议、脱敏输入/输出引用、可选 Token usage、错误码和 UTC 时间。调用外部服务前，调用方需先提交 `RUNNING` span；完成后仅允许从 `RUNNING` 迁移到 `OK`、`ERROR` 或 `INTERRUPTED`。单次耗时由调用方使用 monotonic clock 计算，服务不会从墙钟差值伪造执行耗时。
- `task_event_cursors` 与 `task_events` 以同一事务锁定和分配任务序号。调用方回滚时游标递增和事件行一并回滚。读取服务只提供排序和分页；HTTP/SSE 入口必须先按当前会话检查任务访问范围，不能把 UUID 或证据引用当作授权凭据。
- `audit_events` 记录可信 actor、动作、结果、对象/前后版本引用和脱敏输入哈希。业务动作应与审计插入放在同一数据库事务。PostgreSQL 触发器拒绝更新和删除；业务账号还应遵循只授予所需 INSERT/SELECT 权限的部署策略。
- 当前仓库尚未交付 `agent_tasks` 表，故任务 ID 暂无数据库外键。M2-01 建立任务表后，应通过单独迁移补齐关系；本 issue 不提前实现任务队列、在线埋点或任务 API。

## 敏感内容与证据

运行轨迹只接受 JSON 摘要或不透明证据引用。服务按凭据字段名及常见 Bearer、API 密钥、口令文本模式脱敏；二进制值不会写入 JSON。调用方不得传入隐藏推理、附件原文或未经权限控制的内容。原始文件、字段原值和可下载资源必须存放在受鉴权的业务证据存储中，由独立授权 API 读取；拥有轨迹读取权限不能绕过附件权限。当前服务提供脱敏与引用存储基础，没有新增附件读取 API，因此不声称已完成在线附件授权验收。

输入哈希基于同一脱敏规则后的规范 JSON 计算，不保存哈希输入的原文。若输入全是低熵秘密，哈希本身不等同于加密或匿名化；调用方应对审计字段选择适合的业务输入，并避免把秘密作为待审计输入。

## 中断、Token 与留存

- 协调器可调用 `interrupt_stale_spans` 将超时遗留的 `RUNNING` span 标为 `INTERRUPTED`，记录通用 `EXECUTION_INTERRUPTED`，不补造成功、耗时或具体根因。
- Token usage 为 `null` 表示调用方没有可用 usage；当前基础设施不会填造 Token 数。实际模型/MCP 覆盖率与 `unavailable` 展示需后续真实调用点接入后验收。
- `TRACE_RETENTION_DAYS` 默认 30 天，允许配置 1 至 3650 天。清理函数的调用者须传入仍活动任务和已有正式订单关联任务；函数同时保护仍有 `RUNNING` span 的任务。过期任务事件及已结束 span 可删除；事件游标与审计流水不由该函数删除。任务/订单关系尚未接入前，清理任务必须由未来的生命周期协调器提供准确保护集合。
- 当前未提供清理预览 UI、附件清理、checkpoint 清理或生产留存合规承诺；清理函数仅实现运行轨迹数据基础。

## 验证入口

在 Windows PowerShell 仓库中运行：

```powershell
pwsh -File code/scripts/verify_issue_006.ps1
```

脚本用单独命名的 Compose 项目和 PostgreSQL 数据卷执行迁移、模型一致性检查、固定演示身份初始化和数据库集成测试，结束时只清理该隔离项目及其卷。需要 Docker 和本地 `code/backend/.env`（可依据 `code/backend/.env.example` 设置）。Python 依赖通过容器内 `uv run --frozen` 管理。测试覆盖 Span/脱敏/usage、并发序号、事务回滚、审计不可改写、中断和留存保护。它们是隔离数据库集成测试，不是在线模型、MCP、前端时间线或附件授权验证。
