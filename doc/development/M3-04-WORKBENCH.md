# M3-04 全屏工作台与草稿交互

## 页面入口与数据边界

- 登录后 `/` 显示真实任务创建表单和当前身份可见的最近任务；`/tasks/{task_id}` 可直接恢复该任务。
- 销售和采购文本均调用任务创建 API。文件上传暂未接入，不读取文件，也不显示假解析结果。
- 任务详情先读取授权后的服务端快照，再订阅同源 SSE。页面用服务端状态、用户输入、草稿版本、错误和事件更新界面；SSE 重连时先刷新快照，浏览器用 `Last-Event-ID` 续接。
- 输入补充仅在 API 提供 `INPUT` 等待点时开放。草稿编辑携带当前版本、checkpoint、interrupt 与幂等键。冲突时保留本地未保存编辑并显示提示；任务已离开可编辑等待点后，服务端会拒绝修改。
- 审批决定由服务端验证角色、部门、等待点、版本和内容哈希。批准、退回、拒绝均提交真实 API；退回/拒绝在界面要求填写原因。202 只表示排队受理。只有快照返回真实 `order_ref` 时才显示订单创建结果。
- 任务快照中的 `quota_preview` 只按任务所属部门读取合同及合同余额。超额金额用后端十进制规则计算；额度账缺失或合同不属于任务部门时，不显示可批准的余额。最终额度核验仍由批准和订单提交服务端完成，页面预览不替代事务性校验。

## 交付范围

本 issue 实现全屏任务工作台、销售/采购文本入口、最近任务恢复、运行状态及事件、草稿双向编辑、版本冲突提示、合同额度预览和版本绑定的人工审批操作。审批不能由模型或页面自行确认。PDF、图片、Excel、多轮模型质量评测和 ERP 对接不属于此 issue。

## 验收

在仓库根目录执行：

```powershell
pwsh -File code/scripts/verify_issue_018.ps1
```

验证脚本使用唯一 Compose 项目、独立 PostgreSQL 卷、随机宿主端口和一次性演示密码；运行迁移与 `alembic check`、Python lint/格式/编译、前端生产镜像构建和类型检查，并调用 `test_issue_014.py`、`test_issue_015.py`、`test_issue_017.py`、`test_issue_018.py`。后端用例通过登录会话和真实任务 API 读取快照、编辑草稿、检查版本与金额更新，并确认不能通过跨部门合同 ID 读取额度。

测试记录仅属于隔离数据库中的真实 API 与数据库集成；任务由固定候选夹具建立，没有连接 Worker、在线模型或外部 ERP，因此不作为在线模型评测证据。结束时脚本只清理本轮随机 Compose 项目和卷，不修改 `code/backend/.env`，不接触默认 `tradepilot` 项目数据。

前端本地静态命令：

```powershell
Set-Location code/frontend
npm run type-check
npm run build
```

当前登录会话依赖同源安全 Cookie 与 CSRF。演示账号只有在本地明确启用 `DEMO_MODE=true`、配置 `DEMO_PASSWORD` 并初始化示例数据后才可登录；本实现不会绕过登录保护。
