## 设计范围

原型采用桌面商贸控制台布局，围绕“输入 → 补充 → 核验 → 人工批准 → 正式订单 → 追踪”组织页面。所有客户、合同、订单、统计及评测结果均为原型示例，不代表已有系统运行成果。

## 推荐演示路径

1. 文本提单：10 → 22 → 02 → 01 → 25 → 09 → 19 → 14 → 06 / 23。
2. 多模态：22 → 12 → 03（超额阻断）；调整后重新核验及人工批准。
3. 批量提单：05 → 13 → 20 → 21 → 14 / 06。
4. 工具与评测：16 → 06 → 17 / 24 → 07。

画板是可编辑的界面与状态设计，不是已经连接后端的交互应用。各画板为示例快照；后续编码按 PRD / Spec 实现状态转换、权限、持久化及真实工具执行。

## 视觉规范

- 1440 像素宽桌面画板，导航与主要操作保持固定位置。
- 深色侧栏、冷灰背景与白色工作面；蓝绿色强调主要动作。
- 中文采用 Noto Sans SC，数据与执行标识使用等宽字体。
- 错误使用红色、等待使用琥珀色、成功使用绿色；状态均带文本。
- 8 像素间距基准；边界优先使用留白和细线，避免过度卡片化。
- 文本、图标、字段、表格与轨迹采用可编辑原生图层。

## 交互约束

1. 生成草稿不等于生成正式订单；待批准时明确显示正式订单尚未创建。
2. 缺失规格、单价或日期时高亮字段并提示补充，批准动作禁用。
3. 超额 22 万元相对剩余 15 万元，展示超额 7 万元；填写备注不能解除阻断。
4. 人工批准绑定草稿版本；修改业务字段后提示重新校验与批准。
5. 任务恢复使用原任务 ID；全屏与悬浮窗共享任务与编辑内容。
6. 工具详情展示实际调用的界面结构；原型中的 IO、Token 与耗时标为示例。
7. 批量操作逐笔确认；错误行不可直接批准，部分成功可追溯每张订单。
8. 评测页面区分预期阻断、执行失败与断言失败，不把所有阻断计成失败。

## 审阅清单

- 布局无塌陷、重叠与意外裁切。
- 主操作清晰；禁用、等待、错误、成功均能辨认。
- 文本对比度、中文字体、数字列对齐和表格密度一致。
- 余额、订单金额、超额差额和明细金额相互一致。
- 无人工批准或额度不足时，页面不显示正式订单已生成。
- 页面可追溯至 PRD 与 Spec，示例数据不被描述为实测成绩。
